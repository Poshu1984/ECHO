## 開發流程

| 日期 | 決策 | 出處 |
|------|------|------|
| 2026-11-26 | 每日由 Claude 推進，一天一個 PR，分支名 `claude/daily-YYYYMMDD-<主題>`，PR 標題前綴【Claude 每日】。 | 每日推進排程指示 |
| 2026-11-26 | 工作方式：每天交付一個完整、看得到的成果；寫規格→先寫測試→實作→用真工具驗證→QA 清單；重要成果由三位獨立審查者（正確性、資安隱私、使用者體驗）挑錯，再由評審判定；會取代既有邏輯的高風險功能先「新舊並排、只記錄差異」，老闆確認後才切換。 | 同上 |
| 2026-11-26 | 低風險 PR 在所有檢查通過時可由 Claude 合併；登入帳號、積分付費、用量與成本、使用者資料、資料庫結構、刪除類變更一律等老闆。合併後若線上出問題立即回滾。 | 同上 |
| 2026-11-26 | 公開文件與 PR 不寫未修補的資安細節，只寫「安全性修正」。 | 同上 |
